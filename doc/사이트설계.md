# 사이트 설계

## 1. 근거 자료

- `공덕해링턴스퀘어카다록_20160119.pdf` (14쪽, 공덕경우개발(주) 시행)
- PDF 14쪽 전체(텍스트·사진·지도·도면·디자인)를 분석해 페이지 구성, 본문, 이미지, 디자인을 적용했다.
- 본문은 카탈로그 문구를 그대로 옮겼다(명백한 오탈자 2곳만 수정 — doc/미확인.md).

## 2. 페이지 구성

| 페이지 | 주소 | 구획(섹션) | PDF 근거 쪽 |
|---|---|---|---|
| 홈 | `/` | 메인 비주얼 · 단지 컨셉 · 시설 바로가기 · 랜드마크 · 관심고객 등록 안내 | 1, 2, 3, 9, 14 |
| 사업개요 | `/business/` | 사업개요 · 사업규모 · 시행·시공 | 2, 14 |
| 입지환경 | `/location/` | 입지 지도 · 입지 프리미엄 | 4 |
| 시설안내 | `/facility/` | 호텔 & 컨벤션 · 비즈니스 오피스 · 상가 · 휴식 & 문화공간 | 5, 6, 7, 8 |
| 단지안내 | `/complex/` | 단지 배치 · MD 구성 | 10, 11 |
| 층별안내 | `/floor/` | 공간계획 · 1F ~ 7F 평면 | 11, 12, 13 |
| 관심고객 등록 | `/apply/` | 신청 폼(성함·연락처·문의사항 + 개인정보 동의) | — |
| 개인정보 처리 안내 | `/privacy/` | 설정값(`privacy`) 표시 | — |
| 관리자 | `/admin/` | 로그인 · 목록(검색·상태·기간) · 상태 변경 · 삭제 · CSV | — (검색엔진 비노출) |

- 각 구획은 `data-slot="<페이지>.<구획>"` 표식이 붙는다. 본문 파일이 없는 구획은 "콘텐츠 준비중"으로 표시된다.
- 층별안내는 카탈로그에 있는 1F~7F 만 다룬다. 8F~23F(호텔)는 카탈로그에 평면이 없다.

## 3. 설정 레이어

```
shared/config/base.ts          기본(base)  — 단독으로 완전한 사이트(8페이지)
        ↓ 덮어쓰기
shared/config/templates/       유형(template) — 현재 비어 있음(미적용)
        ↓ 덮어쓰기
shared/site.ts                 현장 설정 — 이 현장 고유값(사이트명, 페이지 구성)
        =
shared/config/index.ts → config (화면·서버·빌드가 모두 이것만 읽는다)
```

- 덮어쓰기 규칙: 객체는 키 단위 병합, **배열은 통째로 교체**(예: `pages` 를 바꾸면 전체 목록을 다시 적는다).
- `shared/site.ts` 의 `overrides` 를 `{}` 로 비우면 기본 사이트(8페이지, 사이트명 "분양 사이트")로 빌드된다 — 이 상태로 빌드되는 것을 확인했다.
- 유형 추가: `shared/config/templates/<이름>.ts` 작성 → `templates/index.ts` 에 등록 → `shared/site.ts` 의 `template` 에 이름 지정.

## 4. 화면 조립 방식

- 페이지마다 `frontend/<key>/index.html` 이 있다(홈은 `frontend/index.html`).
- HTML 안의 표식(`<!--@head-->`, `<!--@header-->`, `<!--@title-->`, `<!--@sections-->`, `<!--@footer-->`, `<!--@privacy-->`)을 **빌드 시** `frontend/build/layout.ts` 가 설정값으로 바꾼다. 그래서 머리말·메뉴·꼬리말·구획이 JS 없이 HTML 에 들어간다.
- 빌드 대상은 최종 설정의 `pages` 다. 설정에 없는 HTML 은 빌드에서 빠지고, 설정에 있는데 HTML 이 없으면 빌드가 멈춘다.

### 본문(콘텐츠) 파일

- 위치: `frontend/content/<페이지 key>/<구획 id>.html` — 빌드 시 해당 `<section>` 안에 그대로 들어간다.
- 개발 서버 실행 중에 고치면 화면이 자동으로 새로 고쳐진다.
- 이미지: `frontend/public/images/` (주소는 `/images/파일명`). `npm run check` 가 본문에 쓴 이미지 경로가 실제로 있는지 검사한다.
- 구획이 2개 이상인 페이지는 머리 아래에 구획 바로가기(탭)가 자동으로 생긴다.

## 5. 디자인

카탈로그 디자인을 웹으로 옮겼다. 값은 `frontend/src/styles/base.css` 맨 위 변수에 모여 있다.

| 요소 | 카탈로그 | 사이트 |
|---|---|---|
| 주색 | 표지·띠 보라 `#492e91` | 머리말, 강조 글자, 버튼, 관심고객 띠 |
| 배경 | 시설 페이지 차콜 `#221f1f` | 페이지 머리, 오피스·휴식공간·사업규모 구획, 꼬리말 |
| 보조 | 섹션 탭 회색 `#6c6e70` | 구획 바로가기 탭 |
| 영문 제목 | 가는 글씨 + 굵은 글씨 2~3줄, 토프색 | `.heading--en` (Barlow 300/600) |
| 국문 제목 | 가는 글씨 + 굵은 강조어(보라) | `.heading--ko` |
| 사진 | 크기가 다른 사진 콜라주 + "이미지컷" 표기 | `.gallery` + 사진마다 "이미지컷" |
| 글꼴 | 윤고딕(YD)·DIN·Myriad·Trajan | Noto Sans KR · Barlow · Cinzel (Google Fonts) — 원본 글꼴 웹 라이선스 미확인 |

### 페이지 추가 절차

1. `npm run new-page -- <key>` → `frontend/<key>/index.html` 생성

3. `npm run check`
